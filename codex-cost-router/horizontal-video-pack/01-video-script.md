# 横屏科普视频脚本

主题：为什么新手用 Codex 额度烧得特别快？因为没有先做任务路由。  
规格：16:9，约 120 秒，真实录屏为主，HTML 插片辅助解释。

## 0-5s
画面：开场标题插片 `intro-title.html`。  
旁白：很多新手第一次用 Codex，额度不是花在写代码上，而是花在“还没想清楚就开始执行”上。  
字幕：额度不是烧在写代码，而是烧在盲目执行。

## 5-15s
画面：GPT 对话框录屏，展示一个很大的模糊需求。  
旁白：比如一句“帮我优化整个项目”，Codex 可能会先读目录、扫文件、推理方案、再反复试命令。  
字幕：大任务 + 模糊目标 = 高上下文成本。

## 15-30s
画面：`token-waste-flow.html` 插片。  
旁白：真正贵的不是某一次回复，而是全项目扫描、高推理、反复执行、权限过宽叠在一起。  
字幕：全项目扫描、高推理、反复执行，成本会叠加。

## 30-55s
画面：当前 Skill 文件夹录屏，展示 `SKILL.md`、`README.md`、`references/`。  
旁白：codex-cost-router 的作用，就是在 Codex 开始读项目、改文件、跑命令之前，先做一次执行前路由。它不直接写代码，而是先判断复杂度、风险、上下文范围、模型档位、推理强度和权限边界。  
字幕：它不是执行器，而是执行前的成本路由器。

## 55-80s
画面：Codex 内调用 Skill 的实操录屏，展示预检报告和优化后的执行 Prompt。  
旁白：它会把“我要做什么”拆成：该不该全项目读取、是否先只读分析、用 Mini 还是更高模型、低推理还是高推理、要不要分阶段。最后输出一段更省 token、更可控的 Codex Prompt。  
字幕：先判断，再执行；先收窄，再开工。

## 80-100s
画面：`model-decision-card.html` 与 `cost-router-flow.html`。  
旁白：轻任务用轻模型，中等任务用标准模型，高风险重构再上高推理。模型不是越强越好，而是要和任务成本匹配。  
字幕：模型选择不是炫配置，而是成本匹配。

## 100-120s
画面：`before-after.html`，再切 `ending-card.html`。  
旁白：直接执行，是让 Codex 自己摸路；先路由，是把路径、权限和预算先框出来。对新手来说，这一步往往比多买额度更重要。记住一句话：先路由，再执行。  
字幕：先路由，再执行。
